# 记忆与回合生命周期

长期记忆由 Hindsight 提供。SQLite 保留原始聊天、情绪状态和用于控制提交的请求元数据。实现分别见 [Hindsight 适配](../../memory/hindsight.py)、[回合服务](../../modules/chat_api/service.py) 与[请求存储](../../storage/turn_requests.py)。

## 三类身份

- **记忆身份**：`x-memory-thread`，浏览器跨谈话保持稳定；不同身份使用独立的 Hindsight bank。
- **聊天会话**：`x-session-id`，新建谈话时改变；用于读取原始聊天历史和会话互斥。
- **回合请求**：`request_id`，每个新回合使用新值，重试原回合时沿用；不能同时改变请求内容或记忆身份。

直接调用 API 而没有指定记忆身份时，采用 `.env` 的 `AX_MEMORY_USER_ID`，再缺省为 `bina-local-user`。这符合当前本地单用户模式。

## 数据归属

| 数据 | 存放位置 | 用途 |
| --- | --- | --- |
| 原始用户与 Bina 消息及来源 `source` | SQLite `chat_turns` | 历史展示、导出与近期上下文 |
| 情绪数值、漂移与交互时间 | SQLite `mood_state` | 当前交互状态 |
| 请求状态、内容指纹、生成结果和提交时间 | SQLite `turn_requests` | 取消、恢复和幂等提交 |
| 会话互斥 | 数据库旁的 `.locks/` 目录 | 跨本机进程拒绝同一会话的并发回合 |
| 事实、偏好、更正与共同经历 | Hindsight bank | 跨会话长期记忆 |

锁目录内使用 SQLite 事务持锁，进程退出会释放锁；服务运行时不要删除目录。该目录不是另一个长期记忆库。

## 回复前读取

服务在会话锁内读取最近五轮原始聊天，每轮分别保留最多 350 字符用户内容和 400 字符 Bina 内容，再加入说话人标签，历史总量小于 4000 字符。先分别裁剪再拼接，可避免长附件或长用户消息吞掉 Bina 回复。

Hindsight reflect 根据本轮输入召回并整理当前事实、旧事实及经历。召回失败返回明确错误，不把未知记忆当作已成功加载。近期历史、长期记忆与本轮输入随后进入 Bina 提示词。

## 生成、取消与提交

1. 获取会话锁并检查请求 ID；同一会话已有回合运行时返回 409。
2. 新请求记为 `generating`，生成回复；生成失败记为 `failed`。
3. 取消操作将仍未提交的请求改为 `cancelled`，也可先登记尚未到达的请求 ID，防止取消与请求到达顺序颠倒。
4. 生成成功后，在同一个 SQLite 事务内检查取消状态、保存原始聊天和生成结果，并进入 `committing`。
5. 使用固定文档 ID、内容与时间戳同步写入 Hindsight，以 `replace` 模式更新该文档；成功后记为 `completed`。

第 4 步是取消边界：取消先完成则不保存聊天或长期记忆；本地提交先完成则继续写入长期记忆，客户端应显示提交状态。HTTP/SSE 断线、浏览器停止与超时会尝试取消。

取消不会强制结束外部模型调用所在的工作线程。线程返回后丢弃已取消结果；在它退出会话锁之前，同一会话仍拒绝并发请求。用户交互已经发生，情绪状态和交互时间可能已更新，取消边界针对聊天与长期记忆提交。

## 失败恢复

本地保存成功而 Hindsight 写入失败时，原始聊天仍可读取。沿用同一请求 ID 和相同请求内容重试，会复用已生成结果继续写入长期记忆，不再次生成或追加本地回合。已完成的请求直接返回保存结果。

浏览器在状态未确认或提交未完成时，保留原请求 ID；在同一页面再次发送相同内容会继续原回合。调用方应自行保存需要跨页面恢复的请求 ID。接口用法见 [HTTP API](api.md)。

## 情绪时间与原子更新

`last_tick_at` 表示数值漂移的时间，`last_interaction_at` 表示用户交互的时间。空闲心跳只推进前者，久别与跨日提示依据后者。旧表首次迁移时以已有漂移时间初始化交互时间；无法从旧字段恢复更早的真实用户交互时间。

漂移、增量和连接重置的读、改、写使用 `BEGIN IMMEDIATE` 事务，避免聊天线程与主动消息线程相互覆盖。状态边界和迁移由[质量回归](../../test_suite/test_quality_regressions.py)覆盖。

## 主动消息与存储演进

主动消息经 `commit_notice` 持有同一个会话锁，锁覆盖生成与本地保存；用户会话忙时本次主动触发跳过。只有成功保存后才降低连接需求、登记冷却并发送通知。其来源写为 `proactive`，不会将 `[proactive]` 系统标记当作用户事实写入 Hindsight；后续真实用户互动仍按正常规则形成长期记忆。

`storage/database.py` 提供连接、原子插入和幂等迁移，版本记录在 `schema_migrations`。首次使用旧库时保留原始聊天，补齐交互时间和来源列；请求结果保存 `version=1`，兼容初版未带版本的结果。业务层使用 `schemas/turns.py` 的请求、结果和状态类型，不再依赖 Python 对象的 `__dict__` 作为格式。
